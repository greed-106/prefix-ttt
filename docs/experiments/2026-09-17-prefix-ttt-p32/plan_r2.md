# P32 第二轮（r2）任务书：A/B 两阶段复跑

启动日期 2026-09-18。本文件是第一轮（`plan.md`）之后的复跑任务书，两者都在同一个稳定实验目录里；
第一轮的账本与总结见 `ledger.md`、`experiment_summary.md`，不覆盖、不重写。

## 1. 为什么必须复跑（第一轮的直接证据）

| 证据 | 数值 | 指向 |
| --- | --- | --- |
| A 阶段到结束时**没有收敛** | 归一化误差 1.23→0.73；`grad_norm` 57.7→**3.79** 仍在下降 | A 的预算不足 |
| A 结束时读出幅度远小于教师 | `readout_rms≈0.043`，约为教师的 4% | 起点差 |
| B 结束时幅度已修正 | 学生/教师读出幅度比**均值 1.36**（层 0/1/2 = 3.7/7.2/3.6，深层 0.54–0.83） | 幅度不是瓶颈，**方向**才是 |
| B 的目标函数**偏离方案** | 实际训练目标是 $\text{CE}+8\,\text{KL}$（`kd_loss` 被误传 `world_size`）；A/B 实测同权重同批：14.5922 → 3.7918 | 第一轮分数不是纯 TTT 架构的公平检验 |
| 真实水平（最终权重直测） | 学生 CE 1.01–1.14、KL 0.19–0.52；教师 CE 0.59–0.78 | 差 0.25–0.55 nat/token |
| 成本 | prefill 40.0 ms、TPOT 26.5 ms、峰值 13.65 GiB、缓存恒定 **64 MiB** | 效率目标已达成，复跑只需保持 |

结论：**A、B 都从零重跑**，不继承第一轮任何 checkpoint；复跑要能回答"目标函数修好之后，
纯 TTT 能接近 E2（MME 1429.49 / POPE 0.8501）到什么程度"。

## 2. A 阶段（注意力迁移预热）的调整

| 项 | r1 | r2 | 依据 |
| --- | --- | --- | --- |
| 数据遍数 | 1 遍（391 步） | **3 遍（1173 步）** | 目标函数结束时仍在下降，说明是预算而非能力受限；A 是最便宜的一环 |
| 目标函数 | $\mathcal L_{\text{full}}+\lambda_V\mathcal L_{\text{vision}}$，$\lambda_V=1$ | 不变 | 视觉监督是本项目核心假设，本轮无反对证据；消融后置 |
| 学习率/调度 | 1e-4，3% warmup + cosine（按 391 步） | 不变，cosine 按 **1173 步**重新铺 | 只动"预算"一个变量 |
| 数据划分 | `manifest['A']`（50k，已审计） | 不变（重复 3 遍） | 保持划分与身份确定性；A 的样本本来就 ⊂ B 的训练集 |
| 逐层幅度诊断 | gate/state/memory/readout RMS | 不变 | 第一轮正是靠它发现幅度问题 |
| 存档间隔 | 每 25 步 | **每 100 步** | 1173 步下减少约 20 GB 无用写入 |

**A′ 验收判据**：结束时归一化误差**明显低于 0.73**（目标 ≤0.5）、`grad_norm` 明显低于 3.79。
若两者都无改善 ⇒ A 已触及线性注意力的表达力上限，**不再延长 A**，直接进入结构实验。

## 3. B 阶段（主训练）的调整

| 项 | r1 | r2 | 依据 |
| --- | --- | --- | --- |
| **KL 归一化** | 误乘 `world_size`（$\text{CE}+8\text{KL}$） | **$\text{CE}+\text{KL}$**（代码与单测已改） | 方案钉死 $\lambda_{KD}=1$；A/B 已证明差别 |
| **日志** | 只记 CE+KL 合计 | **分别记 `loss_ce`、`loss_kl`** | 缺少分解正是本次缺陷藏了两小时的原因 |
| 步数/批次 | 5182 步、有效 batch 128、micro 8、1 遍 | **完全不变** | 与 E2 / E2-full 同预算才能对比 |
| 训练范围 | 32 层 LoRA(r32/α64) + 特征映射 + gate | 不变 | — |
| 学习率 | 新模块 1e-4、LoRA 2e-5、clip 1.0 | 不变 | 单一变量原则 |
| 起点 | A 的 features（gate 非零） | 不变（但 A′ 更好） | — |
| 结束前诊断 | 只有训练 loss | **pilot（391 步）与结束时各跑一次** `dev_loss.py`、结束时跑 `compare_readout.py` | 让"能否追上 E2"在跑完前就有判据 |

**B′ 验收判据**：
1. 日志自洽：`loss_ce + loss_kl ≈ loss`，KL 权重为 1；
2. 结束时真实 CE+KL 低于 r1 的 1.24–1.66；
3. MME Perception > 984.84，方向是追近 E2 的 1429.49；
4. 成本不劣化（prefill ≤ ~45 ms、TPOT ≤ ~30 ms、缓存仍为 64 MiB）。

**若 B′ 仍停留在 985 附近 ⇒ 目标函数不是主因**，此后按单变量依次做结构实验：
① 恢复读出 RMS 归一化 → ② 给部分层保留短窗/anchor → ③ 提高状态表达力（可学习写入尺度、更高秩特征映射）。

## 4. 明确不改的东西（及理由）

- **不改模型结构**（读出无归一化、无 Local-32/anchor、固定 $1/128$ 写入尺度）：先给"预期架构"一个干净基线；
  现在动结构会和 KL 修复混在一起，无法归因。
- 不改数据、模板、预处理、prompt、评测协议、随机种子；不动 `configs/base.json`、`configs/full.json`。
- 不重训 E2/E2-full（用历史数字对照），不做 E1 对照，不做 P32-Basic 消融（后置）。
- 不追 CUDA graph，不动推理代码（成本已达标）。

## 5. 算力安排（待定项）

8 卡当前不可用（0–6 号卡被他人的任务占用 63–65 GB），7 号卡空闲。

| 方案 | A 的成本 | 说明 |
| --- | --- | --- |
| **等 8 卡**（推荐） | 3 遍 ≈ **55 min** | A 与 B 都用 8 卡，与 E2/E2-full 同条件 |
| 单卡先跑 A（1 遍） | **约 6–7 h** | 等于放弃 r2 的"A 加长"；B 仍需等 8 卡（单卡约 55 h，不可行） |
| 单卡先跑 A（3 遍） | 约 19–21 h | 不推荐 |
| 单卡起 A、后续 8 卡 `--resume` 续跑 | 按剩余步数 | 跨 world size 续跑受支持（账本已实测跨 world 目标函数一致，第 391 步 CE 差 0.4%） |

**单卡 A 是否影响 B**：不影响。B 的身份校验只看 A checkpoint 的 `stage`/`complete`/`manifest_sha256`/
`config_sha256`/`samples_seen`/`global_step`，不含 world size；单卡与 8 卡的 A 是同一目标函数、同一批样本、
同一步数，差别只有浮点求和顺序。账本会显式记录 A 的 world size 与遍数。

## 6. 需要的代码改动（清单）

1. `configs/p32.json`：新增 `training.stage_a_passes`（按 §5 的最终决定取值）。
2. `training.py`：新增 `A_STAGE_PASSES` 常量与 `stage_a_trajectory(samples, passes)` 小工具。
3. `transfer.py`：按 passes 重复遍历 `manifest['A']`；`total_steps = passes × ceil(len(A)/128)`；
   cursor / 存档 / `complete` 判定同步；存档间隔默认改为 100。
4. `sft.py`：A checkpoint 校验用同一 total；**分别记录 CE 与 KL**。
5. `config.py`：镜像校验新键。
6. 测试：`test_training.py`（trajectory）、`test_config.py`（新键漂移）、`test_sft.py`（CE/KL 日志自洽）。
7. 产物用新目录，**不覆盖 r1 证据**：`training/A-P32-r2/`、`training/P32-r2/`、`eval-p32-r2/`。
