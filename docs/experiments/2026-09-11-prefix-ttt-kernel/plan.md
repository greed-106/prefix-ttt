## 1. 目标与当前进度

A 阶段 391 步与 E2 阶段 5182 步已完成。当前推理加载 E2 checkpoint 后在内存中合并 LoRA，23 层 Prefix-TTT 加 9 层完整注意力；Local-32 已有单 token 专用路径。本阶段只优化这份已训练方法的实现，不改变训练配方、参数、注意力定义或 benchmark 协议。

当前正式质量基线来自 `/data/shared/weights/prefix-ttt/eval-optimized/postrefactor/`：MME Perception 1429.4893、Cognition 278.2143；POPE Accuracy 0.8501、F1 0.8357。此前未合并 LoRA 的分数不能用作本轮数值基线。已成功的旧评测不重复提交。

成功标准：新路径确实进入正式推理；与原路径输出、递推状态和缓存语义一致，误差符合原有计算精度；真实 checkpoint 的同进程 A/B 显示 kernel 数量与延迟下降；完成 MME、POPE 逐回答及官方分数回归；有配置、日志、队列状态和中文总结支撑结论。是否超越 E0 必须实测，不预先承诺或通过修改 E0 后端实现。

## 2. 已有证据与本轮假设

旧审计显示 660 token 下完整模型计入的 FLOPs E0 8777G、E2 8794G；仅注意力 flash 部分由 228.4G 降至 72.7G。因此“注意力计算减少”不等于“整个模型计算显著减少”：MLP 与投影仍占大头，TTT 又增加特征映射、状态读写、归一化与门控。

早期 6411 对 1395 的 decode kernel 数是两项优化之前的数据。两项优化之后仍有大量特征映射、类型转换、状态中间张量和缓存包装操作，必须重新 profile。旧账本中的 `torch.compile` 与 FLA fused recurrent 尝试减少了 kernel 却变慢；已有微测提示其 Python/guard/预处理成本超过收益。直接 Triton 启动并融合连续数据流仍是不同的、需要验证的方案。

延迟至少由 CPU 发射、GPU 计算、显存流量、同步及它们的重叠决定。将“每 kernel 约 10 微秒”作为旧机器状态下的经验相关性，不作为普适定律。只有 profiler 与不带 profiler 的计时同时改善，才采纳优化。

| 任务 | 工作 | 验证与产物 |
| --- | --- | --- |
| K0 | 核对旧账本、当前代码、GPU/调度器、成功结果；独立审查热点及精度 | 本任务书先建立，随后建立主账本；原始引用与假设明确 |
| K1 | 建立可复用同进程 A/B 测量，单卡依次切换当前 E2/融合 E2，同输入与预热条件；另测 E0 | 分离 prefill/decode 的 CUDA kernel 数、CPU/CUDA 时间、缓存字节；留存 JSON 与日志 |
| K2 | 直接 Triton 融合 SiLU、乘法、RMS；单 token 特征投影若占主导，进一步融合投影与归一化 | 与 ATen 原路径对照 BF16/FP32、非连续输入、真实头维；保留逐算子舍入语义 |
| K3 | 融合 FP32 状态写入与 inclusive read，融合读出归一化、门控与 local 相加 | 单步与多步状态、有效行/已结束行、旧状态不污染；真实 checkpoint logits 与生成对照 |
| K4 | 按 profile 证据消除剩余重复缓存操作或同步，必要时优化 prefill 的同类逐元素链 | 仅保留有独立收益的精准改动，不做缓存架构或训练重构 |
| K5 | 正式 CPU/GPU 回归、E2 MME 与 POPE 评测、同进程性能复测及代码审计 | 与 postrefactor 逐样本比对，逐项解释数值差异；阶段总结、最终账本 |

K2/K3 属于候选，实际采用项由结果决定；失败候选如实记录并回退。实现只增加轻量内部推理分派，训练及 CPU oracle 保留，实验切换位于本目录脚本，不增加面向用户的配置开关。

## 4. 数学与精度不变量

每个 token 的特征为

$$
\phi(x)=\mathrm{RMS}\bigl(\mathrm{SiLU}(xA)\odot xB\bigr).
$$

状态必须先写后读，写入系数仍为 $\eta=2^{-7}$：

$$
S_t=S_{t-1}+\eta\,\phi(k_t)v_t^\top,\qquad m_t=\phi(q_t)^\top S_t.
$$

最终为 Local-32 输出加 signed gate 乘归一化 memory。Local-32 是按有效 token 计数的分块因果注意力，不是滑动窗口；RoPE、9 个 anchor 层和 Flash SDPA 选择保持同一方法语义。

FP32 参数 master 与 FP32 递推状态保留。当前 autocast 会在投影、SiLU、乘法、RMS 返回、门控乘法及残差加法之间形成 BF16 舍入点，融合需显式模拟，不能把整条链悄悄提升精度再只舍入一次。状态乘加是否合并 FMA 也须对照。浮点归约顺序允许出现正常精度差异，但不得用放宽既有测试容差来掩盖错误。

测试覆盖首次/后续 prefill、单 token、31/32/33 边界、多次 decode、padding/空洞/finished 行、不同 batch 与非连续张量。启用 autograd 时仍走原训练实现，现有梯度、因果、分段一致性测试必须通过。

## 5. 实验执行与资源

当前 8 张 H100 均 0 MiB、0% 利用率，无本项目训练、Supervisor 或队列消费者存活；本机旧账本确认从未启用正式 SQLite 队列。用户授权全空闲时可使用所有卡，出现其他任务时仅在物理 6、7 空闲的前提下使用这两张卡。每次提交前复核实际状态。

正式任务由现有 `prefix_ttt.scheduler` 配合已安装 Supervisor 托管，每卡最多一项，不改调度器实现。用绝对 uv 路径、argv 数组和显式 CUDA/HF/线程环境；按阶段独立 manifest/SQLite，失败不自动重试。使用已有本地权重与离线 benchmark 缓存，不下载或重复复制资产，不新增 SHA256 校验或通用门槛。

性能 A/B 用同进程交替顺序，冷编译与预热排除，计时与 profiler 分开，报告中位数和波动。microbenchmark 用于定位，不冒充端到端收益。正式评测可以跨卡并行，但性能结论以同卡、同进程 A/B 为准。长任务观察间隔按运行时长降至分钟级，不高频轮询。
