# Mamba 阅读：从选择性状态空间到 Prefix-TTT 的硬件优化

阅读日期：2026-09-17。本篇续接本目录的 Prefix-TTT kernel 实验，论文依据为用户上传的 [Mamba PDF](../../paper/Mamba%20Linear-Time%20Sequence%20Modeling%20with%20Selective%20State%20Spaces.pdf)：Albert Gu、Tri Dao，*Mamba: Linear-Time Sequence Modeling with Selective State Spaces*，arXiv:2312.00752v2，2024-05-31，共 36 页。官方论文标识为 [arXiv:2312.00752](https://arxiv.org/abs/2312.00752)，作者代码仓库为 [state-spaces/mamba](https://github.com/state-spaces/mamba)。本篇阅读的是 Mamba 原论文，不将后续 Mamba-2 的算法归入该论文。

本文将“论文声称”“我们的推导”和“本项目已有事实”分别标出。论文中的性能数字是作者在其软硬件和模型上的结果；本阶段是否超越 Flash SDPA，以本目录后续账本、原始测量与总结为准。本文没有开展 Mamba 训练或复现实验，也没有把研究候选写成已采用实现。

## 1. 研究问题：怎样压缩历史，同时保留内容选择能力

**论文声称。** Transformer 的注意力保留逐 token 的 K/V，因此能按当前查询访问历史，却需要随长度增长的缓存，prefill 的注意力计算也随长度二次增长。固定大小的递归状态可以把每一步生成成本控制在与历史长度无关的范围内，但是否有效取决于状态保留了哪些内容。此前很多结构化状态空间模型为了使用高效卷积，采用不随输入改变的动力系统；这种限制在语言等离散数据中尤其突出。

论文 §3.1 用两个任务说明这一问题。普通 Copying 的输入和输出间隔固定，只记住时间关系就可能成功；Selective Copying 把有用符号之间的无关 token 数量随机化，模型必须根据内容决定保留什么。Induction Heads 则要求看到一次 “Harry Potter” 后，在后续 “Harry” 处取回 “Potter”，需要把关联写入状态，再根据上下文读出。二者共同要求的是沿时间维控制信息，而不仅是在层末增加逐点乘法门控。

**我们的分析。** 用户指出的相似性成立于“状态递推可以改写成前缀计算，并按 GPU 存储层级实现”这一层面。它不意味着 Mamba 与 Prefix-TTT 表达同一个函数。尤其是本项目的 signed readout gate 调制当前输出，不能自动等同于 Mamba 对过去状态的遗忘机制。区分这两种门控，才能避免把架构变化误称为纯 kernel 优化。

## 2. 从连续系统到输入相关的递推

### 2.1 为什么旧 SSM 可以用卷积

论文 §2 从一个输入通道出发，写出连续状态系统。用 $u(t)$ 表示输入、$h(t)$ 表示 $N$ 维状态：

$$
\frac{\mathrm{d}h(t)}{\mathrm{d}t}=Ah(t)+Bu(t),\qquad y(t)=Ch(t).
$$

按步长 $\Delta$ 做零阶保持离散化，得到

$$
\bar A=\exp(\Delta A),\qquad
\bar B=(\Delta A)^{-1}\bigl(\exp(\Delta A)-I\bigr)\Delta B,
$$

$$
h_t=\bar A h_{t-1}+\bar B u_t,\qquad y_t=Ch_t.
$$

这里的矩阵逆表达用于说明离散化关系；奇异点可由对应解析函数的连续延拓理解。论文采用对角结构，实际计算可以按状态坐标处理。

当参数与时间无关、初态为零时，展开递推即可得到

$$
y_t=\sum_{j=1}^{t}C\bar A^{t-j}\bar B u_j.
$$

其中权重只依赖距离 $t-j$，因此可以预先形成卷积核。FFT 提供并行训练路径，而逐步生成仍使用递推。效率来自同一数学对象的两种求值方式。

### 2.2 选择性怎样改变问题

**论文方法，§3.2。** 让 $B_t$、$C_t$、$\Delta_t$ 由当前输入产生，$A$ 仍为学习得到但跨时间共享的参数。为区分批量与输入映射矩阵，以下用 $B_{\mathrm{batch}}$ 表示批量大小。对输入形状 $[B_{\mathrm{batch}},L,D]$，论文 Algorithm 2 中 $B_t,C_t$ 的整体形状为 $[B_{\mathrm{batch}},L,N]$，$\Delta$ 为 $[B_{\mathrm{batch}},L,D]$，状态为每个通道的 $N$ 个坐标。

其递推写作

$$
h_t=\bar A_t h_{t-1}+\bar B_t u_t,\qquad y_t=C_t h_t.
$$

沿一个已给定输入序列，状态转移仍是对旧状态的仿射变换；整个输入到输出的映射则不再是固定线性系统。展开后，过去 token 的系数包含沿途输入相关的转移乘积，通常不再只依赖相对距离，因此固定卷积核失效。

论文 Theorem 1 给出直观特例。令 $N=1$、$A=-1$、$B=1$，并令 $\Delta_t=\mathrm{softplus}(z_t)$，则

$$
\bar A_t=\exp\bigl(-\mathrm{softplus}(z_t)\bigr)=1-\sigma(z_t),\qquad
\bar B_t=\sigma(z_t).
$$

因此

$$
h_t=(1-g_t)h_{t-1}+g_tu_t,\qquad g_t=\sigma(z_t).
$$

小门值让旧状态保留，大门值让当前输入覆盖旧状态。这说明输入相关的离散步长可以承担 RNN 门控的作用。论文实际模型采用更高维状态；该特例是解释机制，不是完整 Mamba 的全部公式。

## 3. 前缀并行的数学前提是什么

**我们的推导，对应论文 §3.3 的 associative scan。** 把一个时间步记为仿射变换 $f_t(h)=a_t\odot h+b_t$。先执行 $(a_1,b_1)$、再执行 $(a_2,b_2)$，组合结果是

$$
(a_1,b_1)\star(a_2,b_2)
=\bigl(a_2\odot a_1,\;a_2\odot b_1+b_2\bigr).
$$

这一运算由函数复合而来，满足结合律，却一般不满足交换律。于是可以做保持时间顺序的 parallel prefix scan，同时得到每个前缀的变换，再作用于初态。工作高效的树形 scan 在线性总工作量下具有对数并行深度；真实 GPU 实现仍需处理线程通信、块边界与驻留资源，不能把理论深度直接解释为延迟。

这里关键的可并行条件是：当前层的 $a_t,b_t$ 能由已知输入先行产生，不依赖尚未求出的 $h_{t-1}$。若改成一般的状态相关非线性更新，上述固定仿射变换的 scan 便不自动成立。Mamba 的“输入相关”保留了这个结构，因而既提高表达能力，又保住了可并行求值方式。

## 4. 真正的硬件贡献：不要把扩展状态全部写回显存

**论文方法，§3.3.2、附录 D。** 朴素实现先在 HBM 中生成离散化后的参数，再把 scan 的所有状态写回 HBM，最后读出并投影到输出。输入和输出大小为 $O(B_{\mathrm{batch}}LD)$，中间状态却是 $O(B_{\mathrm{batch}}LDN)$。扫描本身的运算简单，额外流量很容易比算术成本更昂贵。

论文将离散化、scan、与 $C_t$ 的读出融合：只从 HBM 加载紧凑输入和参数，在寄存器、共享内存等片上存储中展开状态，计算后写出压缩后的结果。按 Algorithm 2 的张量形状，更完整的紧凑输入规模包括 $O(B_{\mathrm{batch}}L(D+N)+DN)$；论文以 $D$ 相对 $N$ 较大时的主导项概括其 IO。重要的是避免 $L,D,N$ 三个维度在 HBM 中同时展开，而不是把论文的渐近式当成某台卡上的精确字节预算。

长序列不可能整条放进 SRAM。附录 D 明确使用 chunks，并通过中间 scan 状态衔接后续块。因此“状态只在片上展开”也不等于“任意长序列的所有边界都不需要显存”。能融合多少、块如何交接，是有限片上容量约束下的实现问题。

训练还面临另一种状态物化：反向传播需要前向中间值。论文不保存所有逐步状态，而是在反向加载紧凑输入后重算状态；并对完整 block 中便宜但占内存的激活采用重计算。**本轮只优化推理 prefill，不执行或声称完成这部分反向优化。**

**我们的分析。** FlashAttention 同样通过分块和片上计算避免把巨大中间张量写回 HBM，不过保留 softmax 注意力的二次算术量。Mamba 的贡献是在具有不同数学结构的递推中贯彻这种 IO 思想。迁移到 Prefix-TTT 时，应问“哪些大的临时状态仍在 HBM 中生成并重复读取”，而不是以“使用了 scan”作为新优化的充分证据。

性能口径尤其值得照着核对。附录 E.5 的核心算子基准使用 A100 80GB PCIe、BF16、batch 1、模型维度 1024、SSM 状态维度 16，长度从 512 增至约 500K；注意力为因果 FlashAttention-2。它排除了 QKV 投影等核心操作以外的费用。端到端生成则固定 2048 token prompt、128 token generation，改变 batch，重复三次取平均，其中 6.9B Mamba 是未训练模型。Table 15 的训练显存为 125M 模型，Mamba 与优化 Transformer 接近，但表中 Mamba 的实际数字略高，不能复述成所有设置下显存更低。

**本项目已有事实。** 上一阶段 [实验总结](experiment_summary.md) 记录 H100、PyTorch 2.7.1、Triton 3.3.1 环境中的 kernel 优化；640/1536 token 下的完整混合模型仍未追平 E0。这些历史结果提醒我们：局部算子的复杂度和速度不足以决定完整模型速度。本轮公平比较应固定相同输入形状、相同 BF16 与共享 QKV/O 权重，并以包含特征、Local-32、门控和缓存生成的完整注意力模块为主指标。比较对象具体为本项目锁定版本的 PyTorch Flash SDPA，不泛化成所有 FlashAttention 版本。

## 6. 与 Prefix-TTT 的严格对应及差异

本阶段开始时的 Prefix-TTT 使用下列 additive matrix-state 更新。这里 $r$ 为特征维度，$d_v$ 为 value 维度：

$$
S_t=S_{t-1}+\eta\,\phi(k_t)v_t^\top,\qquad
m_t=\phi(q_t)^\top S_t,\qquad
\eta=2^{-7}.
$$

这是先写后读，当前 token 包含在自己的前缀中。$S_t$ 的每头形状为 $r\times d_v$；当前生产形状为 $128\times128$。它没有 Mamba 的输入相关遗忘转移，也不是包含预测误差反馈的 delta rule。特征映射为 SiLU 双投影乘积后的 RMS，完整输出还包含 Local-32 与有符号线性门控。Local-32 按有效 token 计数划分不重叠块，每块内部因果注意力；它不是滑动窗口。

数学上，令 $\Delta S_t=\eta\phi(k_t)v_t^\top$，我们的前缀只是矩阵加法的 scan，结合运算比 Mamba 的仿射组合更简单。但硬件代价未必更小：32 个头的 FP32 状态合计为每样本 2 MiB；只保存单个最终状态很小，逐 token 保存 32768 个状态却需要 64 GiB，尚未计入输入和其他中间量。这是完全物化的思想实验，不是当前 FLA 已经分配了 64 GiB。

我们的更新与读出具有矩阵乘结构，更适合块 GEMM 和 Tensor Core；Mamba 原论文的通道独立、对角状态转移则直接适合逐元素仿射 scan。照搬后者的线程映射，可能放弃前者最有价值的矩阵复用。应迁移 IO 原则，并保留适合矩阵状态的计算形式。

本轮起点也不是逐 token Python 循环。锁定 FLA 版本 `c51953382397da5c3b7b8a41e568915b703e2934` 已提供分块线性注意力：默认 tile 64 使用 `chunk_linear_attn(normalize=False)`，其他已有 tile 通过无 gate 的 `chunk_simple_gla` 路径。上阶段还实现了特征尾部融合、readout 尾部融合、RoPE 融合及准备期 BF16 权重副本。因此，“分块”“融合”本身属于已有能力；本阶段要验证的是减少剩余包装和 IO、提高 GEMM 效率是否仍有净收益。

## 7. 可检验的优化方向与研究边界

**我们的研究假设。** 第一类机会在 FLA 外围：全有效输入仍进行的 mask 处理，Q/K 两条路径的重复布局转换和小 GEMM，及能保持既定舍入语义的逐元素中间量。这些优化对短序列可能更有价值，因为 launch 与数据准备尚未被大算术量摊薄。

第二类机会在块大小和状态组织。每块先形成 $K_j^\top V_j$，通过块间前缀提供入口状态，再用 $Q_jS_j$ 读出历史、用因果块内乘积处理当前块。块增大会减少边界数量，却增加块内二次项和片上资源需求。由此应做单项消融，而不是凭渐近复杂度指定最大块。

第三类是后续训练研究：按块重计算降低反向激活驻留，并联合分析训练吞吐与显存。但这需要独立的梯度、数值稳定性和训练结果验证，不属于本轮推理实现。输入相关遗忘、低秩状态或改变特征维度也可能是方法研究方向，必须另立实验并重新训练，不能以提升速度为由悄悄改变已训练函数。

论文自身 §5 指出实证规模有限，尚需验证更大模型的 scaling、下游交互能力，以及连续/离散模态间的归纳偏置取舍。对本项目还要增加三项限制：FP32 存储不保证不同归约顺序逐位一致；长序列性能收益不保证在既有短上下文任务上同样出现；完整层速度超过 softmax 注意力也不代表两者质量相同。此前真实 checkpoint 对归约变化敏感，所以最终采用必须同时有算子 oracle、缓存接续、真实层输出及必要质量回归证据。

后续实现与测量按 [教学推导](teaching_mamba_prefix.md) 建立可检查的数据流。性能、失败候选和实际采用项归入主账本与新的阶段结果；本文保留为论文和设计依据，不代替实验记录。
